# chartui revisit, 2026-09-15

All three spikes from [DESIGN.md](../DESIGN.md) are built, run, and committed. Work is
paused here before phase 1. The spikes are still in the tree because two of their
questions need a person looking at real output, and because deleting them costs nothing
later.

## Where the repo is

Scaffolded from `calcipy_template` 5.5.2, Python 3.13, `rich` as the only runtime
dependency with `textual` behind an extra. `linecast` is a dev dependency used by spike 1
as the float-raster reference and nothing else. Nothing under `chartui/` exists yet
beyond the template's `__init__.py`.

The spike code lives in `spikes/` and is shaped like the target package layout, so phase
1 is closer to a move than a rewrite. `spikes/out/` holds every rendered frame and is
gitignored. Each spike has a `FINDINGS-<n>.md` next to it, and `spikes/README.md` gives
the run command and what to look at.

```sh
uv run python spikes/spike1_canvas.py       # four charts x six glyph strategies, plus linecast
uv run python spikes/spike2_layout.py       # one-pass vs fixed-point frame, prints the column-cost table
uv run python spikes/spike3_transitions.py  # 1/2/3 frame counts, t tween, e easing, space swap, q quit
```

## Decided

**Glyph selection stays per-mark and overridable, and octants do not become the
default.** WezTerm renders octants correctly with the current font, so font support is
not the blocker DESIGN.md expected it to be. Braille still wins on some data and some
chart types, which means the choice belongs to the mark and the caller rather than to a
capability probe picking the highest resolution available. This makes phase 4's terminal
probing a fallback for terminals that cannot show a glyph family at all, not an upgrade
path that promotes octants once it detects support.

**The bitmap canvas is the right model.** Against linecast's float framebuffer it gives
up sub-pixel antialiasing on strokes and translucent overlap between series. None of the
four sample charts needed either, and the antialiasing difference reads as smoother
rather than as necessary.

**The one-pass frame stays.** The pessimism costs exactly one column, only on
multi-series charts, at every width from 40 to 160.

## Open, and what each one blocks

Three findings from the spikes that should land in DESIGN.md, and two questions only a
person can answer.

A background-layer fill never sets a bit, so a min-max band renders as nothing but its
median line with color off. linecast has the same problem for the same reason, so this is
inherent to the fill model rather than to the bitmap choice. `AreaMark` needs a secondary
encoding (a border stroke, a dither, or an outline glyph) to survive `NO_COLOR`. Blocks
phase 2.

`time_ticks` sizes tick density off a flat per-tick width estimate, but the first tick is
formatted fuller than the rest because it has no neighbour to distinguish itself from. At
high density it overwrites the second label, visible as `09:009:01` in
`spikes/out/two-converging-series-160col-ten-minutes-onepass.txt`. The first tick needs
its own width budget. Blocks phase 1.

Every render measured 19 to 32 ms against a 16 ms budget, across three independent
spikes, and the cost scales with cell count rather than series count. It comes from the
spike's dict-keyed cell storage and from allocating a `Segment`, a `Style`, and a `Color`
per cell. Phase 1's `canvas.py` and `surface.py` need flat arrays indexed by
`cy * width + cx` and cached styles before any budget claim holds, and the 10-frame
transition recommendation is a bet on that fix rather than a measured result.

Spike 2 also found that a single width-aware check (`width - left_gutter - reserve >=
MIN_DATA_WIDTH`) matched the fixed point in every case tested, at zero iterations. That
is a better legend rule than the series-count heuristic the spike used to manufacture a
measurable difference.

Still unanswered, both needing a person:

- whether the tween reads as motion or as noise, and whether 20 frames looks smoother
  than 10 (watch `spikes/out/spike3.gif`, or run spike 3 and toggle with `t` and `e`)
- whether the tick ladder reads at 40 columns, where it allows two or three ticks total
